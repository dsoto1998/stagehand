<objective>
Add per-track chord chart support. Each track row gets a small chord chart icon inside row-name-col (left of the song title). The icon is dim when no chart exists and accent-colored when a chart is assigned. Clicking the icon opens a modal with two tabs: "Upload PDF" and "ChordPro". PDF files are stored as ArrayBuffer, ChordPro as string — both persisted in IDB via the existing saveMeta pattern. PDF is displayed via iframe blob URL; ChordPro is rendered as a chords-above-lyrics layout.

Purpose: Musicians often need chord charts alongside their rehearsal tracks. Having charts per-track and accessible from the track row removes the need to switch to a separate app or printed sheet.

Output: Working chord chart icon in every track row, functional modal with PDF upload + ChordPro editing, IDB persistence.
</objective>

  <name>Task 2: Implement chord modal logic — tabs, PDF upload/display, ChordPro parse/render, IDB persistence</name>
  <files>renderer/js/ui-controller.js</files>
  <action>
Add a `showChordModal(trackId)` function to ui-controller.js (near the existing `showInfoModal` function, around line 238). This function:

1. **Opens modal:** Gets the track from `tracks` array. Sets `#chord-overlay` to `.show`. Stores `chordModalTrackId = trackId` in module scope.

2. **Tab switching:** Attach click listeners to `.chord-tab` buttons. Active tab gets `.active` class. Show/hide `.chord-tab-content` divs (`#chord-tab-pdf` and `#chord-tab-chordpro`) via `display: '' / 'none'`.

3. **Load existing data on open:**
   - If `track.chordPdf` (ArrayBuffer): Create a `Blob` from it with `type: 'application/pdf'`, create a blob URL via `URL.createObjectURL(blob)`, set `#chord-pdf-preview` innerHTML to `<iframe src="${blobUrl}"></iframe>`. Show the clear button.
   - If no PDF: Set `#chord-pdf-preview` innerHTML to `'No PDF uploaded'`.
   - If `track.chordPro` (string): Set `#chord-chordpro-input` value to it. Call `renderChordProPreview()` to populate `#chord-chordpro-preview`. Show the clear button.
   - If no ChordPro: Clear textarea and preview.

4. **PDF upload:** Click handler on `#chord-pdf-upload` triggers `#chord-pdf-input.click()`. On the file input's `change` event, read the selected file as ArrayBuffer via `FileReader`. Store the ArrayBuffer in a local variable `pendingChordPdf`. Display in iframe via blob URL. Show clear button.

5. **PDF clear:** `#chord-pdf-clear` click sets `pendingChordPdf = null`, `pendingChordPdfCleared = true`, resets preview to `'No PDF uploaded'`, hides clear button.

6. **ChordPro live preview:** On `#chord-chordpro-input` `input` event, call `renderChordProPreview()`.

7. **ChordPro clear:** `#chord-chordpro-clear` click clears textarea and preview, hides clear button.

8. **renderChordProPreview()** — Parses the textarea value and renders into `#chord-chordpro-preview`. The parser:
   - Split input by `\n`
   - For each line:
     - If line matches `{title:...}` or `{t:...}` — render as `<div class="cp-directive"><strong>title</strong></div>`
     - If line matches `{comment:...}` or `{c:...}` — render as `<div class="cp-directive">comment text</div>`
     - If line matches `{subtitle:...}` or `{st:...}` — render as `<div class="cp-directive">subtitle</div>`
     - If line matches `{start_of_chorus}` or `{soc}` — add a `<div class="cp-directive">[Chorus]</div>`
     - If line matches `{end_of_chorus}` or `{eoc}` — skip (no output)
     - Otherwise: Parse `[chord]` tokens. For each segment between brackets, output `<span class="cp-chord">chord</span>` followed by the lyric text. Wrap line in `<div class="cp-line">`.
     - Empty lines → `<div class="cp-line">&nbsp;</div>` (visual break)
   - Set innerHTML of `#chord-chordpro-preview`

9. **Save handler:** `#chord-save` click:
   - Get the track object from `tracks` array by `chordModalTrackId`
   - If `pendingChordPdf` exists: `track.chordPdf = pendingChordPdf` (keep as ArrayBuffer)
   - If `pendingChordPdfCleared`: `track.chordPdf = null`
   - Set `track.chordPro = document.getElementById('chord-chordpro-input').value || null`
   - CRITICAL for IDB: The saveMeta pattern strips arrayBuffer. But chordPdf is also an ArrayBuffer. To persist it correctly, call `saveMeta` with the chordPdf field included. Since saveMeta does Object.assign on the existing IDB record, and chordPdf is a NEW field (not the audio arrayBuffer field), this works fine. The `saveTrackMeta` helper strips only `arrayBuffer` (the audio data). So create a custom save: `const { arrayBuffer, ...meta } = track; await LibraryManager.saveMeta(meta);` — this passes chordPdf through since it is NOT named `arrayBuffer`.
   - IMPORTANT: Before saving chordPdf to IDB, `.slice(0)` it to avoid detachment: `if (track.chordPdf) meta.chordPdf = track.chordPdf.slice(0);`
   - After save, call `renderCurrentTab()` to refresh row icons.
   - Call cleanup to close modal.
   - Revoke any blob URLs created during the session.

10. **Close/cancel:** `#chord-close` and `#chord-cancel` click, Escape key, and clicking overlay background all call cleanup. Cleanup: remove `.show` from overlay, revoke blob URLs, clear pending state.

